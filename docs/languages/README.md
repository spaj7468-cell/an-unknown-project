# Language guide template

Every programming language receives the same predictable hierarchy so developers can find information quickly, while the content remains specific to that language.

## Standard chapter tree

1. **Identity and use cases**
   - What the language is designed for; strengths, limits, common deployment targets.
2. **Setup**
   - Supported toolchains, installation, version manager, first program.
3. **Syntax and semantics**
   - Names, expressions, statements, scope, control flow, functions.
4. **Data model**
   - Primitive and compound values, collections, mutability, equality, copying.
5. **Types**
   - Static or dynamic typing, inference, generics, nullability, conversions.
6. **Functions and composition**
   - Parameters, return values, closures, modules, interfaces, traits, classes where applicable.
7. **Errors and exceptions**
   - Error categories, propagation, recovery, diagnostics.
8. **Memory and execution**
   - Allocation, ownership or garbage collection, stack/heap concepts, runtime behavior.
9. **Concurrency**
   - Async model, threads/tasks, shared state, cancellation, synchronization.
10. **Standard library**
    - Text, collections, files, dates, networking, serialization.
11. **Tooling**
    - Formatter, linter, compiler/interpreter, debugger, package manager, build system.
12. **Testing**
    - Unit and integration testing, test doubles, property-based tests where relevant.
13. **Project structure**
    - Modules, dependency boundaries, configuration, logging.
14. **Security and performance**
    - Common hazards, profiling, safe defaults, dependency hygiene.
15. **Practical projects**
    - Small exercise, realistic app, deployment-ready example.
16. **Troubleshooting and reference**
    - Common error messages, FAQ, glossary, official documentation links.

## Compare languages fairly

Compare languages by task and constraints—not by a single “best language” score. Include runtime, ecosystem maturity, deployment target, team familiarity, performance profile, safety guarantees, maintainability, and operational cost.
